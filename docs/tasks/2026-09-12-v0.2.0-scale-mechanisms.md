## 目標

讓基礎層不加特例就撐得起中大型專案。
遠因：對照兩個既有中大型專案（一個多路線管線、一個三方協作系統）的治理需求，基礎層缺四項通用機制：
程式與文件的耦合檢查、多本帳、任務單分夾、Claude Code 以外的強制點。
近因：使用者問「這個樣板對中大型專案的治理足夠嗎」，回答是「骨架夠、機制差四項」；使用者裁定先補再推 GitHub。

## 範圍

- doctor：`coupled` 檢查（第 14 項）與 `--changes staged|all`；`ledgers` 設定與 `check_limits` 跑遍所有帳本；tasks 遞迴掃描；`Ctx.changes_mode`
- `tools/install_git_hooks.py`：乾跑／`--apply`／`--uninstall`，備份既有 hook
- `.claude/hooks/pre_commit_check.py` 改傳 `--changes all`
- Anvil 自己宣告一條耦合：改 `tools/doctor.py` 必須同時改 `tests/test_doctor.py` 與 `CHANGELOG.md`
- 文件：extending.md 延伸點與「規模變大時的加法」、TEMPLATE_README 步驟 7 與最小用法、AGENTS 掛點三列、limits L01 解除與 L06 新增
- 測試四個：coupled 兩模式、ledgers、tasks 遞迴、install_git_hooks

## 明確不做

- 不內建多代理人工作流（locked 狀態、後審）；那是延伸層
- 不做 pre-push hook；先觀察 pre-commit 夠不夠
- 不推 GitHub（本任務收關後、由使用者裁定的下一步）
