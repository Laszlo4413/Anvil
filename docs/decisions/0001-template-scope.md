# ADR-0001：Anvil 的定位與範圍
Status: accepted
Created: 2026-09-12
Updated: 2026-09-12
Expiry: [standing]

## 脈絡與問題

**遠因**：使用者在 `D:\AI project` 下有多個與 AI 代理人協作開發的專案（XivForge、五個 Python 工具、AI-OS），
各自長出不同的結構與文件慣例，沒有統一標準。2026-07-15 曾用一份「專案架構守則」統一過 Python 工具的
工程結構，但那份只管目錄、pyproject、版本號，不管協作紀律。

**發展**：XivForge 在 VRChat V5 收關後的盤點裡，連續發現三層文件（根 README、線 README、CHANGELOG）
落後現況近一個月，開案文件「專案綱要」的里程碑表自 2026-07-16 起就沒再更新，即使各版本資料夾內的
PLAN 與缺陷清單都維護得很勤。根因是：紀律沒有強制點，只能靠代理人「記得」，而上下文壓縮讓「記得」無法持久。

**近因**：2026-09-12 使用者決定開一個獨立的樣板專案，以後新專案一律複製它起步；既有特殊架構的專案
（XivForge 的多線引擎結構）在其下延伸而不推翻。研究方法採雙來源交叉驗證：三個自家專案群找「獨立收斂」
的慣例，加上社群近一到兩年的做法即時查證。研究結論在 `D:\AI project\_研究報告_專案樣板雙來源交叉比對.md`。

## 使用者裁定原話（逐字）

- 2026-09-12：「找出最適合當作AI開發新趨勢的標準化專案樣板,以後這個樣板完成就會推上github 之後要開新專案我就會以這個樣板做基礎之上來開發」
- 2026-09-12（研究報告與待裁定問題提出後）：「同意
並依照你的建議開始進行
專案樣板的名稱依你建議」
- 更早（見討論筆記）：「決定不能只以 XivForge 單一專案當基礎」，因為它的慣例是為特定領域長出來的，直接當基礎會過擬合。

## 選項（含被拒選項與被拒理由，必填）

1. **基礎層 + 延伸層兩層樣板，基礎層只收跨情境驗證過的協作紀律**（採用）：語言無關的規則檔、狀態檔、
   三種紀錄、doctor 檢查、commit hook；Python 工具的工程慣例當一個 profile 附在 docs/。
2. **以 XivForge 現有結構反推成樣板**（拒絕）：它的版本夾地質層、契約缺陷清單、母版保護規矩是為「多引擎轉檔 +
   高頻實驗除錯」長出來的，其他專案用不到，會稀釋真正重要的規則。使用者自己否決了這條。
3. **照搬 AI-OS 的治理架構**（拒絕）：AI-OS 有最完整的文件生命週期工具，但它需要「第一個 tool call 必須先讀
   AGENTS.md」的阻斷規則才能運作、讀一個章節要四到五次工具呼叫、連續 32 個版本都在重構治理本身，
   而且它自己的 strategic-review 已承認三方協作的效益「沒有強訊號」。只抽它的中繼資料設計，不搬架構。
4. **採用社群全套 spec-driven 工具（Spec Kit 等）**（拒絕）：每次任務約 800 行 markdown，Thoughtworks 與多篇評論
   指出審不動、小改被膨脹成大流程。單人情境用固定骨架的任務單（約一頁）即可。
5. **做成 Claude Code plugin 而非樣板 repo**（拒絕）：樣板的核心是 AGENTS.md、rules、settings.json，這三樣 plugin
   裝不了；等多個專案要共用同一組 skills 時再抽 plugin。

## 決定

Anvil = 基礎層樣板 repo。內容以研究報告第 5 節為準：根目錄六件、`docs/{decisions,limits.md,tasks,archive,_templates}`、
`tools/doctor.py` + `doctor_ext/` 掛點、`.claude/{settings.json,hooks,rules,skills}`、Python profile。
基礎層不得含任何特定領域詞彙；專案專屬規則走 AGENTS.md 最後一節的掛點。
第一個套用對象是 Anvil 自己（dogfood），第二個是 XivForge（依研究報告第 6 節對照表），五個 Python 工具不回頭改。

## 後果與何時該重審

- 正面：新專案開工時已有強制點（hook + doctor），文件過期會被抓出；規則短、每條有檢查點，代理人遵守率高。
- 負面／代價：多了一種文件（ADR）與中繼資料要維護；hook 只在 Claude Code 內生效（見 limits L01）；
  Python 以外的語言要自己寫 profile（L04）。
- 重審條件：(a) 出現第二種語言的專案；(b) 三個以上專案都要共用同一組 skills（考慮抽 plugin）；
  (c) doctor 的豁免清單開始變長（代表規則訂太寬，這是 AI-OS 走過的路）。
